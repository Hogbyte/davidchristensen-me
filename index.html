Selected work

Each entry gives the problem, what I did, and the result. Details are general because the work is internal to Procore.

Frontend lead for a new compliance data model

Problem

A new compliance feature needed new statuses and new endpoints. The frontend and backend teams had different views of what the UI must read and write.

What I Did

  • Wrote the frontend technical analysis: endpoints, data types, statuses, and a nested feature-flag pattern. Split the work for 2 other engineers.
  • Found that endpoints for two required views did not exist. They moved into scope before build started.
  • Proposed a simpler data model shape and a clearer URL design. The backend team adopted both.

Result

The final design kept my API contract and component structure. Some details changed in negotiation, which is how a shared contract should work.

Testing federated micro-frontends inside a real host

Problem

Our micro-frontends load inside other teams' pages through module federation, and nothing tested their integration. A dependabot dependency upgrade that I merged broke a shared viewer in 3 host products, while the synthetic monitors stayed green (they only checked that the remote was reachable).

What I Did

  • Explained the failure and the monitor gap. Added a mandatory host check to our dependency-update process.
  • Designed a shared Playwright test suite, so a test can load a pull request preview UI branch into a real host.
  • Built a CircleCI workflow that runs each service's smoke tests against its UI preview branch and posts the result on the pull request.

Result

That failure class is now caught before pull requests merge.
